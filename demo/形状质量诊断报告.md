预标注形状质量诊断报告
========================
生成时间: 2026-10-21
工具: tools/probe_prelabel_v2.py（只读，不修改data/annotations）


一、问题现象
------------
界面上所有标注对象看起来都是矩形方框，怀疑描边代码画错了。
排查后确认：描边代码没问题，是「标注数据本身就是矩形」。

实测 data/annotations/ 共 150 个文件 / 898 个对象，其中
  - 745 个（83.0%）是多边形只有 4 个顶点、且x 只有两个值、y 只有两个值
    —— 即纯粹的轴对齐矩形
  - 153 个（17.0%）是真实轮廓


二、根因（两层）
----------------
【第一层：抽稀算法有bug —— 已修复】
core.py 的 simplify_polygon() 用 Douglas-Peucker 抽稀，而D-P 是按
「开放折线」设计的：把首尾连成一条线段，看各点到它的距离。
掩码轮廓是「闭合环」，首尾两点重合 -> 该线段长度为 0 ->
所有点到它的距离都很大 -> 每轮都判定必须保留 -> 行为完全退化。

实测：1000 点的圆被抽成 9 点（近似正八边形），面积误差 9.9%。
这正是「圆看起来像方块」的直接原因。

修复方式（与 canvas/geom.js 的 simplifyClosed 思路一致）：
  1. 去掉闭合环重复的尾点
  2. 在「离首点最远的对角点」处切成两条开放链，分别 D-P，再拼回
  3. 删掉二分搜索里的提前 break（原来 mid=0.025 就退出，
     误差容差被放大到约 24 像素，形状被压成近似矩形）

修复效果：
  1000 点圆    : 9 点 / 误差 9.9%   ->  128 点 / 误差 0.04%
  300 点不规则 : --                ->  179 点 / 误差 0.02%
  6 点 L 形    : 6 点              ->  6 点（原样保留）
新增 7 项单元测试锁住该行为。

【第二层：配对逻辑失效 —— 本次修复】
prelabel.py 的 _prelabel_one() 原本用 IoU 把两个模型的输出配对：
  - seg 模型（实例分割）：形状准确，但类别名用 COCO（bed / dining table...）
  - YOLO-World（检测）  ：类别完全正确（我们的十类），但只有矩形框

两者类别体系不同、框位置大量错开，IoU 配对成功率实测为 0%。
配不上的框走「兜底分支」，被直接造一个矩形多边形。
结果 898 个标注里 745 个（83%）变成方框。

修复方式：不再要求类别一致，改为「以框为锚，向 seg 借形状」
  1. 框定「标注什么类别、在哪个位置」（信 YOLO-World，类别是对的）
  2. 在所有掩码里找「有多少比例落在这个框里」最高的那个（问 seg）
     新增 mask_box_coverage() 度量覆盖率，取代 IoU
  3. 覆盖率 >= 0.55  -> 用框的类别 + 掩码的形状（两者长处都用上）
  4. 覆盖率 >= 0.25  -> 用框的类别 + 掩码的紧致外接框
  5. 完全没有对应掩码 -> 才用真矩形兜底
  6. 未被用上的掩码，若其COCO 类别名恰好在十类内，直接收进来


三、新旧方案对比（150 张图全量，只读验证）
--------------------------------------------
                  旧方案      新方案
    对象总数        576   ->    576      （完全一致，不漏标不重标）
    矩形占比100.0%  ->   45.7%
    平均顶点数       4.0  ->    69.1      （真实轮廓 vs 方框）

前 10 张图抽样：矩形占比 100% -> 33.3%，平均顶点数 4.0 -> 94.5

注：新方案的 45.7% 是在「未去重」输出上统计的。真实流程还会执行
_dedup_same_class()，它优先保留面积大的对象（即有真实形状的那些），
因此最终落盘的矩形占比应低于 45.7%。

覆盖率分布（27 个框样本）呈明显双峰，无调参空间：
  高峰：20 个框覆盖率 >= 0.87（几乎完全重合）
  低谷： 5 个框覆盖率 <= 0.15（几乎无重叠）
  中间区域几乎为空
=> 阈值定在 0.25~0.55 之间命中率完全一致（78%~81%），
   说明判断是干净的二值逻辑。保留 0.55 作为保守值。

剩余矩形对应「seg 模型确实分割不出来」的场景：物体过小或严重遮挡。
