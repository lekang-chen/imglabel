【项目概述】
一句话说明需求：
  让标注人员在 30 分钟内完成 190 张室内场景图片的三模式标注
  （目标检测 / 实例分割 / 语义分割）。

核心设计：
  以实例掩码为唯一核心标注对象。
  检测框 = 掩码外接矩形自动生成；语义掩码 = 实例掩码按类别合并自动派生。
  人工只修改掩码一次，三种格式自动同步。

【迭代轮次】
轮次 1（R1）：官方预训练权重
  预标注模型：YOLO-World (yolov8s-world.pt) + YOLO26n-seg (yolo26n-seg.pt)
  人工修正：60 条（21 类别修正 / 39 边界修正，共 26 张图）
  修正率：58.7 %
  形状质量：矩形占比 39.0 %，平均顶点数 71.0（形状修复前为 83.0 % / 4.0）

轮次 2（R2）：自训权重回标
  基线权重：yolo26n-seg.pt（微调）
  训练配置：epochs=100（早停于 51 轮）, batch=8, imgsz=640, 设备=RTX 5060 Laptop (8.5GB)
  回标方式：用 model/best.pt 对同一批图重新预标注（独立目录，不覆盖 R1 草稿）
  修正率：50.9 %（需人工修正对象 527 → 319，少改 208 个）
  检测 mAP@0.5：0.718 / 掩码 mAP@0.5：0.442
  （best.pt 在「60 条修正后的最终标签」上实测，验证集 30 张，可由
    python tools/eval_best.py 一键复现，指标与数据状态一并落在
    data/best_metrics.json）

轮次 3（R3）：模型调优（冻结主干继续微调）
  起始权重：R2 的 best.pt（不是从官方权重重新开始）
  训练配置：freeze=10（冻结主干）, lr0=0.0005 余弦退火, epochs=50, batch=8, imgsz=640
  回标阈值：conf=0.40（换权重后重新标定，理由见下）
  修正率：50.2 %（需人工修正对象 319 → 292，再少改 27 个）
  精确率：0.498 / 召回率：0.469
  检测 mAP@0.5：0.720 / 掩码 mAP@0.5：0.568

  为什么调优要「从 R2 权重继续」而不是重新训：
  R2 的权重已经完成了「十类编号对齐」这件事，从它出发只精修形状，
  不会把已经学对的东西再冲掉。对比实验见 tools/exp_train.py，
  5 组策略在同一个验证集上的结果：
      head（冻结主干，从官方权重起步）  检测 0.699 / 掩码 0.533
      lowlr（低学习率全量微调）        检测 0.726 / 掩码 0.515
      head_long（冻结+余弦退火 80 轮）  检测 0.707 / 掩码 0.538
      head_hi（960 分辨率训练）        检测 0.683 / 掩码 0.511
      continue（从 R2 权重继续微调）    检测 0.720 / 掩码 0.568  <- 采用
  前四组都出现「掩码涨、检测掉」或两头都不如，只有「从现成权重继续微调」
  做到了掩码 +28.5% 而检测不掉。

  为什么回标阈值要从 0.25 改到 0.40：
  模型迭代后置信度的绝对数值会整体平移（同一张图原本 0.30 的框变成 0.25），
  阈值不动就会凭空多出一堆低分框。实测 150 张图上：
      conf=0.25 -> 809 个草稿，精确率 0.405
      conf=0.40 -> 582 个草稿，精确率 0.498（与 R2 的 0.491 持平）<- 采用
  「换权重必须重标阈值」本身是这次调优得到的一个结论。

轮次 4（R4）：分类别置信度阈值 + 迭代第三轮权重
  做法：不再对十类用同一个 conf，改为按类别分别标定（稀有类放宽、常见类收紧）
  修正率：50.2 %（需人工修正 306 / 总对象 609）
  精确率：0.497 / 召回率：0.490
  检测 mAP@0.5：0.728 / 掩码 mAP@0.5：0.580   <- 150 张数据集口径的最后一轮

轮次 5（R5）：换类补样 —— 把「床」从零样本变成会认（本轮的最后一轮）
  背景：任务书十类中的 bed，在首轮 150 张数据里样本极少（COCO 室内场景里床出现率低），
       预标注几乎标不出床。实测 4 张含床的图，模型漏标 2 张。
  做法分三步，每步都用同一套 val 名单量一遍：
    ① 把第 10 类由 book 换成 bed，长度不变（都在位置 9），
       检测头不重建，前 9 类的权重原样继承 —— 比从官方基座重训划算得多
    ② 自采 / 补采含床图片入池，累计 bed 训练样本 27 个实例
    ③ 以 R4 权重为起点续训（--ft --unfreeze，解冻主干，70 轮早停）
  实测（同一批 30 张 val）：
    bed 检测 mAP50    0.107  →  0.259  →  0.552   （14 → 22 → 27 个训练实例）
    bed 掩码 mAP50      —    →  0.200  →  0.354
    总体检测 mAP50    0.749  →  0.765  →  0.791
    总体掩码 mAP50    0.537  →  0.547  →  0.570
  召回实测：4 张含床图全部检出（原来漏 2 张），2 张无床图未出现误报。
  零样本 vs 微调的误检对比：零样本补标 20 个框里 6 个完全错（最严重一张把
  整张杂物桌判成床，占画面 88%）；训过 14 个样本后 20 个框里 0 个完全错。

【当前 model/best.pt 的最终实测】（评委一键复现口径）
  命令：python tools/eval_best.py
  数据：190 张数据集，验证集 30 张 / 135 个实例
  标注状态：864 个对象，其中 82 条人工修正
  检测 mAP50 0.794（mAP50-95 0.573），精确率 0.704，召回率 0.731
  掩码 mAP50 0.577（mAP50-95 0.308），精确率 0.510，召回率 0.624
  结果同时写入 data/best_metrics.json（含测量时间戳与当时的数据状态）
  说明：R5 之后验证集随数据扩充而更换，绝对值与 R1~R4 不可直接横向比较；
       同口径可比的只有「未动的 9 类」，在 30 张 val 上的摆动为 ±0.08（噪声带内）。

对比结论：
  经过两轮迭代 + 一次调优，掩码 mAP@0.5 从 0.442 提升到 0.568（+28.5%），
  检测 mAP@0.5 保持 0.720；草稿对象数由 898 降至 582，精确率由 0.413
  提升至 0.498，修正率由 58.7% 降至 50.2%，需人工修正的对象从 527 个
  降到 292 个（少改 235 个，降幅 44.6%），验证了
  「预标注→人工审核→训练→回标」迭代闭环的有效性。
  R5 进一步证明：闭环里最有效的动作不是「多训几轮」，而是「把词表里
  最弱的那一类补上样本」—— 同一份权重，补 21 张含床图就让床的
  mAP 从 0.107 涨到 0.552，超过调参带来的全部收益。
  注 1：掩码 mAP 在旧标签（83% 是外接矩形）上曾测出 0.474，换成真实轮廓
  后一度降到 0.415；人工修正 60 条之后重测回升到 0.442，继续微调后达到
  0.568，说明轮廓质量的提升确实被指标捕捉到了。
  注 2：R3 的召回率 0.469 低于 R2 的 0.498，是「精度换回来的代价」——
  继续微调让模型更保守，漏掉的对象略多但标出来的更准。由于修正率本质是
  1−精确率，这个取舍在人工成本上是划算的；但要诚实说明：召回确实降了。
  注 3：所有 mAP 都由 python tools/eval_best.py 在当前仓库的最终标签上
  实测，评委可一键复现，指标与数据状态一并落在 data/best_metrics.json。

【运行方式】
方式一（一键启动，评委复现用这个）：
  双击仓库根目录的 启动.bat
  脚本会自动：找 Python → 建 .venv（已有则复用）→ 补依赖 → 启动 → 开浏览器
  首次装依赖约 5-10 分钟，之后启动几秒；5000 被占用会自动换端口
方式二（命令行）：
  python -m venv .venv
  .venv\Scripts\activate
  pip install -r requirements.txt
  python app.py

【使用入口：上传照片直接开始】
  打开页面后，点左上角「上传照片并标注」，选中自己的照片（支持多选），
  系统会在一次操作里完成：上传入库 → 自动预标注 → 打开第一张新图。
  也可以把图片直接拖进浏览器窗口任意位置。
  上传只处理新增的图，不会覆盖已有图片上的人工修正（60 条修正安全）。
  实现细节：EXIF 方向自动纠正；长边 > 1920 自动等比缩小；
  同名文件自动加 _2/_3 后缀，且连同标注文件一起查重，杜绝串标注。

【删除照片：软删除，可恢复】
  鼠标移到左侧列表的某一行，右侧出现 ×，点它删除（图片与标注一起走）。
  确认框会写明这张图有几个对象、其中几条是人工改过的；
  数据集自带的那 150 张还会额外警告「删了提交口径就对不上」。
  不直接销毁，而是搬到 data/_trash/<时间戳>/，列表上方出现
  「已删除 N 张 · 恢复」，点一下连同修正标记一起拿回来。
  接口对删除名单做白名单校验（只认当前列表里存在的文件名），
  路径穿越（../../app.py）会被判为不存在而拒绝。
