# 人机协同图像标注系统

室内场景图像标注迭代工具 —— 预标注 → 人工审核修正 → 导出数据集 → 模型训练 → 回标，形成完整迭代闭环。

> **仓库已自带完整数据**：`data/images/` 150 张图 + `data/annotations/` 150 个标注 JSON
> （含已完成的 60 条人工修正），clone 后直接启动即可看到全部内容，无需另外准备数据。
>
> | 想核验什么 | 看哪里 |
> |---|---|
> | 60 条人工修正是否真实 | `records/修正记录.csv`（每行含图片名 + 对象 ID，可在界面逐条指认） |
> | 两轮迭代效果对比 | `records/对比结果.csv`（修正率 58.7% → 50.9% → 50.2% → 50.2%，掩码 mAP 0.442 → 0.568 → 0.580，召回 0.469 → 0.490） |
> | 系统能力 | 启动后界面右上角显示 已审核 150/150、修正 60/60 |
> | 提交物清单与实测数据 | `提交信息.txt` |
> | AI 使用过程 | `ai_log.md`（按轮次记录，含踩坑与决策依据） |
> | 一句话看全貌（用法 + 优缺点 + 改进方向） | `项目说明书.md` |
> | 自主学习每一代的账 | `records/自主学习记录.csv`（新增修正数 / 新旧指标 / 采纳与否 / 原因） |

## 快速开始

### 方式一：双击启动（评委复现用这个）

双击仓库根目录的 **`启动.bat`**（或 `start.bat`），一个窗口跑完所有步骤：

1. 找到可用的 Python（`py` / `python` / `python3` 依次尝试）
2. 没有 `.venv` 就自动创建；已有则直接复用
3. 缺依赖就自动 `pip install`（清华源，失败自动切阿里云源）
4. 启动服务并自动打开浏览器

首次运行要装依赖（约 5–10 分钟），之后启动只要几秒。

**想在手机上用**，看手机和电脑是不是同一个网络：

| 情况 | 双击 | 手机打开 |
|---|---|---|
| 同一 Wi-Fi（或电脑连手机热点） | **`手机访问.bat`** | 窗口打印的 `http://192.168.x.x:5000` |
| 手机在外面、用流量，电脑在家 | **`外网访问.bat`** | 窗口打印的 `https://xxx.trycloudflare.com`，扫二维码最省事 |
| 上一条打出地址但手机报 **530**（校园网封 7844） | **`外网访问_备用.bat`** | 窗口打印的 `https://xxx.run.pinggy-free.link`，走 SSH/443 绕开 |

前者只监听局域网（首次会问防火墙权限，点「允许」）；后两者走临时隧道，
地址每次启动都变，关窗口即失效，**拿到地址的人能完全操作，别外传**。
备用通道是 pinggy 免费版，**60 分钟断一次**，断了重开脚本即可。
默认的 `启动.bat` 只监听本机，别人访问不到——这是有意的。

**5000 端口被占用时会自动改用 5001/5002……**，实际地址打印在窗口里。

```bash
python -m venv .venv
.venv\Scripts\activate

### 打开页面后怎么用

**点左上角「上传照片并标注」**，选中自己的照片（可多选）——
上传完成后会自动预标注，然后直接跳到第一张新图开始改。
也可以把图片**直接拖进浏览器窗口任意位置**，效果一样。

左栏「上传后自动预标注」取消勾选，就只上传、不自动标注。

> 上传只处理新加进来的图，**不会覆盖已有图片上的人工修正**。
> 图片会自动按 EXIF 纠正方向，长边超过 1920 会等比缩小（推理更快），
> 同名文件自动加 `_2`、`_3` 后缀，不会串标注。

**删照片**：鼠标移到左侧列表的某一行，右边出现 `×`，点它即可删除
（图片和标注一起走）。确认框会告诉你这张图有几个对象、其中几条是人工改过的。
删掉的东西不是直接销毁，而是搬到 `data/_trash/<时间戳>/`，
列表上方会出现一条「已删除 N 张 · 恢复」，点一下完整拿回来（含修正标记）。

> 为什么不做真删除：那 150 张图连着 60 条人工修正，手滑一次就没了。
> 软删除的成本只是多占一点磁盘，换来的是「删错了也能救」。

> 预标注功能需要 `yolov8s-world.pt` / `yolo26n-seg.pt`（约 40 MB，未纳入仓库），
> 首次点「预标注」时由 ultralytics 自动下载（内置多源回退）；
> **仅浏览界面、审核与修正标注不需要联网**。
>
> 桌面快捷方式 `人机协同图像标注系统.bat` 由 `python tools/make_shortcut.py` 生成。

## 核心设计

> **以实例掩码为唯一核心标注对象。**
> 检测框 = 掩码外接矩形自动生成；语义掩码 = 实例掩码按类别合并自动派生。
> 人工只需修改掩码一次，三种格式自动同步，不存在检测框与掩码对不上的问题。

底层数据模型见 `core.py`，三种模式的渲染实现见 `canvas/app.js`。

## 使用流程

| 步骤 | 操作 | 产出 |
|---|---|---|
| 0 | 左上「上传照片并标注」 | 自己的图片入库 + 自动生成草稿（一步完成） |
| 0b | 列表行右侧 `×` | 删除这张照片（图片+标注移入 `data/_trash/`，可恢复） |
| 1 | 左侧「预标注」 | YOLO-World + YOLO26n-seg 生成草稿标注 |
| 2 | 逐张人工审核 | 改类别 / 修边界 / 补漏标，每次改动自动记入修正记录 |
| 3 | 左侧「导出数据集」 | `dataset/` 下生成 YOLO txt、实例掩码、语义 PNG 三种格式 + 格式自检 |
| 4 | 左侧「训练」 | 自动探测硬件配置，微调产出 `model/best.pt`；右上角进度卡实时显示第几轮、百分比、预计剩余 |
| 5 | 左侧「回标」 | 用自训权重重新预标注，进入第二轮迭代 |
| 6 | 左侧「对比结果」 | 各轮 mAP 与修正率对比 |
| 4b | 左侧「自主学习」开关（可选） | 攒够 20 条修正自动跑一代：续训 → 验证集打分 → **过线才换权重**，否则候选留档作废。记录在 `records/自主学习记录.csv` |

> **为什么自动学习还要设闸门**：训练不保证更好（同配置换种子掩码 mAP 就抖 ±0.035），
> 自动 + 直接覆盖 = 让机器有权把更差的模型换成验收权重。所以装上的原则是
> **指挥权在人，执行权在机器**：候选权重掉超过 0.02 就否，`best.pt` 一个字节不动。
> 实测六种续训配方在「数据没变」的前提下都没过闸门（最好 0.518 vs 0.580），
> 详见 `ai_log.md` 第二十一至二十二轮。
>
> **闸门立得住的另一个前提：验证集不能漂。** 早先每次导出按 20% 现抽，
> 150 张抽 30 张、157 张抽 31 张，同一个种子抽出两批几乎不相交的图——
> 同一份权重在两套考卷上测出 0.728/0.580 和 0.781/0.556。现在验证集钉在
> `data/val_split.json`，只分一次，新图一律进训练集。
> **加新图时它会自己换成基座重训**：续训那条路 `freeze=10` 冻结主干，学不进新场景。

### 审核时的快捷操作

| 操作 | 方式 |
|---|---|
| 撤销 / 重做 | `Ctrl+Z` / `Ctrl+Shift+Z`（或 `Ctrl+Y`），工具栏左侧也有按钮 |
| 描边时撤回上一个点 | 画布右键，或提示条上的「← 撤回一点」 |
| 结束多边形 | 双击 / `Enter` / 点「完成描边」 |
| 放弃当前多边形 | `Esc` 或点「放弃」 |
| 删除选中对象 | `Delete` |
| **模型只圈了一半** | 选中它 → 工具「框选修形」→ 在物体外面拉一个框 → 「并入」（框内那块并进轮廓）；边缘还不准就再用「挖掉」把多出来的地方修掉，或用「画笔」补 |
| **模型多圈了桌子/杂物** | 同上，模式选「挖掉」 |
| **轮廓完全不对** | 同上，模式选「替换」，轮廓直接变成这个框；框里多进来的部分再用「挖掉」去掉 |

> 「框选修形」是确定性的几何操作（框内像素并入对象位图掩码，再提回多边形），
> 不依赖再猜一次模型。起因见 `ai_log.md` 第十三轮：模型对一张被茶几遮挡的
> 长条组合沙发只认到右半边，换更大模型、提分辨率、上 SAM 框提示都救不回来——
> 这是模型能力边界，剩下那半截只能人来给。工具要做的就是把「人来给」压到一次拖拽。

撤销采用**整图快照**（深拷贝整份标注，栈上限 50 步）：
新增、删除、改类别、画笔改形状都能一键回退，
新增对象的随机 id 也能原样恢复，不存在「撤销后对不上号」的问题。

node tools/test_geom.js       # 33 项：前端几何算法

python tools/e2e_delete.py    # 18 项：删除→回收站→恢复端到端（需先启动服务）
```

共 **303 项**。覆盖：
- 核心层：几何工具、掩码转多边形、三格式一致性、导出自检、边界情况、
  PNG 存盘往返一致性（防调色板模式回归）、闭合环抽稀精度（防形状退化成矩形）、
  **导出坐标越界夹取**（贴边物体不再产出负坐标）、
  **上传与列表的扩展名一致性**（webp 上传成功却「不存在」的事故回归）、
  **全量预标注的覆盖闸门**（有修正却没过确认的请求必须被 409 挡回）、
  **训练日志解析**（未开始/启动中/第 N 轮/完成/失败五种状态、轮内百分比、
  两个 mAP、早停、ANSI 控制码剥离）、**权重备份保留策略**（连训多次时
  baseline 不能被「只留 3 份」清掉）
- 几何层：缝隙追踪的面积精度、闭合环 D-P 抽稀、鞍点配对、顶点数上限
- 交互层：复选框筛选、聚焦模式、画笔涂抹/擦除、轮廓描边、
  **撤销/重做**（新增/删除/改类别/改形状四类操作的撤销与重做、栈上限、重做分支清空）、
  **上传入口**（多选/默认勾选、非图片被拒且不发请求、拖拽遮罩显隐）、
  **删除照片**（每项都有删除按钮、取消确认不发请求、请求只带一个名字、
  点 `×` 不误触选中、恢复提示条显隐、**删当前图时取消待执行的防抖保存**）、
  **框选修形**（并入/挖掉/替换三种模式对轮廓与面积的作用、无选中与框过小时的
  边界行为、并入后可撤销）、**手机触屏**（抽屉开关与互斥、遮罩关闭、触摸描边、
  触摸双击闭合、多指不抢占、画布已禁用默认触摸手势）、
  **预标注的作用域**（只标缺少标注文件的图、0 对象的空标注不重做、按钮上标出待标张数）、
  **训练进度浮层**（轮次与百分比、预计剩余、按钮禁用防双开、收起后不反复弹但
  跑完必须弹一次、失败要说清原因且告知旧权重未覆盖）
- 端到端：真的 POST 一张图 → 刷新列表 → 自动触发预标注 →
  预标注只带新文件名 → 完成后自动打开新图 → 统计刷新；
  真的删一张图 → 图片与标注成对进回收站 → 恢复 → 标注里的 `edited`
  标记还在 → 图片数回到初始值

> `ui_test.js` 在 `?uitest=1` 模式下会禁用落盘，自动化测试**不会污染真实标注数据**。
> `e2e_upload.js` / `e2e_delete.py` 会真写文件，跑完（含异常退出）自动删除自己造的
> 图片与标注，并把 `data/state.json` 的运行日志原样还原；上传端到端的预标注用桩替换、
> 不跑模型，几秒结束。

> **调试提示**：`ui_test.js` 启动时会比对「服务端返回的测试脚本」与「本地文件」，
> 不一致直接报错退出。这是为了防一个曾踩过的坑——测试脚本存在两份副本，
> 改的是没被加载的那份，跑出来全是旧结果且全绿，看起来一切正常。
> 遇到「改了没生效」先看这条。

## 质量评估与迭代对比

```bash
# 1. 评估当前草稿质量（对照 COCO 官方真值）
python tools/eval_draft.py

# 2. 用自训权重回标到 data/annotations_r2（不覆盖 R1 草稿）
python tools/relabel_r2.py

# 3. 对比 R1 / R2 的修正率
python tools/compare_rounds.py

# 4. 生成 records/对比结果.csv
python tools/make_compare_csv.py
```

### 实测结果

| 指标 | R1 官方权重 | R2 自训权重 | R3 调优后 | R4 迭代+分类别阈值（当前） |
|---|---|---|---|---|
| 草稿对象数 | 898 | 627 | 582 | 609 |
| 需人工修正数 | 527 | 319 | **292** | 306 |
| 正确对象数 | 371 | 308 | 290 | **303** |
| **修正率** | **58.7%** | **50.9%** | **50.2%** | **50.2%** |
| 精确率 | 0.413 | 0.491 | 0.498 | 0.497 |
| 召回率 | 0.600 | 0.498 | 0.469 | **0.490** |
| 检测 mAP@0.5 | — | 0.718 | 0.720 | **0.728** |
| 掩码 mAP@0.5 | — | 0.442 | 0.568 | **0.580** |

> mAP 为 `model/best.pt` 在**最终修正标签**上的实测值（验证集 30 张），
> 可用 `python tools/eval_best.py` 一键复现，结果写入 `data/best_metrics.json`。
>
> 召回率下降不是模型变差：R1 是两个模型配合、倾向多标（精确率仅 0.413），
> R2 起改成单一自训模型、只标有把握的。**要人改的对象从 527 一路降到 292**，
> 这才是闭环的价值。详见 `ai_log.md`。
>
> R3 是第七轮调优的结果：从 R2 权重出发、冻结主干继续微调，掩码 mAP 从
> 0.442 提到 0.568（+28.5%）而检测 mAP 不掉。代价是召回略降 0.029，
> 且置信度整体平移，回标阈值须同步从 0.25 校准到 0.40 —— 这一步的取舍
> 与实验过程写在 `ai_log.md` 第七、八轮，可用 `python tools/exp_train.py` 复现。
>
> R4 是第十一轮的结果，两个改动：
> ① 继续迭代微调（copy_paste 分割增强 + 120 轮长训 + 分类损失提权），
>    检测/掩码 mAP 双涨；同配置换随机种子复现，检测侧 0.728-0.733 稳定，
>    掩码 0.55-0.58 在噪声带内，报告以较低值计。
> ② **按类别定置信度阈值**（`data/class_thresholds.json`，由
>    `tools/tune_threshold.py` 生成）：十类难度差距太大（laptop 22 个
>    训练样本 vs person 174 个），统一 0.40 顾此失彼。150 张全量实测，
>    分类别阈值把 F1 从 0.722 提到 0.758，漏检少 68 个、误检多 47 个——
>    漏检要手画一笔（贵），误检点一下就删（便宜），这个交换是划算的。

## 数据准备

推荐方式（**不下载 815MB 整包**，实测 59 秒完成 150 张）：

```bash
# 1. 只取标注文件
curl -L -o data/coco/instances_val2017.json https://hf-mirror.com/datasets/merve/coco/resolve/main/annotations/instances_val2017.json

# 2. 按类别均衡策略选出 150 张，从官方直链逐张抓取 + 压缩
python tools/prepare_data.py --fetch-url --coco-ann data/coco/instances_val2017.json --out data/images
```

传统方式（下载整包，慢）：

```bash
python tools/fast_download.py http://images.cocodataset.org/zips/val2017.zip data/coco/val2017.zip --threads 12
python tools/prepare_data.py --coco-ann data/coco/instances_val2017.json --coco-img data/coco/val2017 --out data/images
```

筛选说明自动写入 `data/data_source.txt`，可据此填写 `提交信息.txt`。
